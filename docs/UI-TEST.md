# UI acceptance checklist — Mac companion + iPhone

The Mac menu bar layout was visually accepted on October 30, 2026; the Settings window is the next UI focus. This is a **manual review for the current prototype**, not a claim that each interaction has been tested on a physical device. Record which build you used, and take screenshots of visual inconsistencies where helpful. Hide the connection passcode, IP address, and paired-device names in screenshots you share.

## Mac companion

- [ ] **Rebuild and relaunch** Stats Companion from Xcode (older built apps may still carry the generic icon). The menu bar icon now shows the original blue chart mark instead of the SF Symbol; clicking it consistently opens a compact status panel. Click outside and open it again.
- [ ] Passcode is readable in both light/dark appearances; **Refresh is to the left of Copy** in both the menu and Settings. Both icons have clear hit targets and VoiceOver labels. Copy shows short **Copied** feedback. Refresh generates a **different** five-digit code with a new five-minute countdown; the previous code no longer pairs. There should be **no brief Generating passcode… state or layout flicker**, including on automatic expiry.
- [ ] With no iPhone connected, the network row reports discoverability/port and the device row says **No devices connected**. The yellow device icon is centered with its text while the network icon remains aligned with the start of multiline status. A failed listener should show a warning and useful explanation, not a green success state.
- [ ] The Stats menu panel should be about **312 points wide**, with compact passcode digits, 13-point action labels, tight separators and short rows. Hovering Website, About, Changelog, Settings and Quit, or selecting with **Up/Down**, should show a **blue selection with white text/icons/shortcuts** instead of a gray background. Test **Return**, **Space**, **Escape**, **⌘,** and **⌘Q** (Quit last).
- [ ] Click **Website**, **About**, **Changelog**, and **Settings**, one at a time. Each opens its destination without deliberately dismissing the menu panel; preserve the previously accepted popup behavior. Repeat a safe item via Tab then Return/Space. Other Mac windows must remain open.
- [ ] **Tab/Shift-Tab** cycles menu selection through Refresh, Copy, available actions, Open at login, and Quit. Open the menu and press **Shift-Tab first** (without a preceding click or Tab): it should select the last action; Tab then goes forward. The selected action shows a visible highlight; **Return/Space** activate it. Avoid accidentally invoking Quit during testing.
- [ ] **Settings** opens in front in a compact **460 × 675-point** window, with no titlebar separator or oversized blank area above Passcode. Check the passcode label, outlined copy icon, muted grey section backgrounds, 13-point row text, section spacing and corner radii. There should be no scrollbar or extra "Paired phones" block when no phones are registered.
- [ ] The Settings passcode header shows **Expires in M:SS**, updates every second, and includes circular **Copy** and **Refresh** native glass controls. Copy briefly shows its checkmark; Refresh rotates to a different code and resets the timer without leaving copied-state feedback behind. On macOS 26+, the Quit button should have native translucent glass and Feedback & Support should use blue prominent glass, both pill-shaped.
- [ ] **Settings** shows only two status rows by default. The yellow no-device indicator aligns with its text; the network row's info button opens **Manual connection** with a selectable address and a compact circular **Copy** icon directly alongside it (including a tooltip and VoiceOver label). If no address is available yet, the info icon can be absent.
- [ ] **Dock**, **Menu Bar**, and **Open at login** switches are flush to the right, with the description text legible without awkward wrapping. The secondary **Quit Stats Companion** capsule stays at the bottom left and the blue **Feedback & Support** capsule at the bottom right. With paired phones, the list appears and can scroll without hiding the footer.
- [ ] **Changelog** opens with a compact header in the normal macOS system font design (not rounded), a circular native glass Back button, and Apple's **native** soft scroll-edge effect when text moves underneath the fixed top bar on macOS 26+. There must be no permanent dark/gradient stripe when scrolled to the top. The scrollbar follows macOS settings. Tab can focus Back and Return activates it. Website and Feedback & Support open their expected browser pages.
- [ ] **Tab/Shift-Tab** works immediately in Settings without first clicking a control: Refresh, Copy, connection info (when available), updates, Website, About, Changelog, Dock, Menu Bar, Open at login, paired-phone Revoke (when present), Quit and Feedback are reachable. On a fresh opening there should be **no unsolicited blue focus ring**. Press Tab, then Shift-Tab (and try Shift-Tab as the first key after opening); a visible native focus ring should follow selection. Click a control or blank area: the keyboard focus ring should clear, without preventing mouse interaction; Tab should show it again. **Space/Return** activate the currently keyboard-focused control. Tab remains native inside the manual-connection popover or revoke alert, and keyboard navigation does not jump between separate app windows.
- [ ] The **About** action from either the menu or Settings opens the same compact **280 × 232-point** window with the **same original blue chart icon as both app icons**, version/build, and two lines: **© 2026 Ishtiaq Ul Haq Syed.** and **All Rights Reserved.** Reopening focuses the same window instead of creating duplicates.
- [ ] With the Dock enabled, choose **Help → StatsCompanion Help**. The Help menu item should retain its familiar **lightbulb icon**, while the unavailable-Help alert says **“Help isn’t available for StatsCompanion.”** and shows our blue chart application icon instead of the generic placeholder. Dismiss the alert and verify the rest of Settings remains usable.
- [ ] **Dock** and **Menu Bar** controls work independently; one remains visible. Enable Dock and check its actual tile shows the same blue chart logo as About (not a generic app icon); the macOS menu bar should not acquire an unnecessary **File** menu or **New Settings Preview Window** command. While the app is running, close Settings and click its Dock icon: Settings should open in front. Repeat with Settings already visible or on the Changelog page; the existing Settings window should return to the home page without duplicates. Then hide the menu-bar icon (while keeping Dock enabled) and check the Dock shortcut still works. Disable/re-enable Dock to test the dynamic policy change. Restore your preferred visibility when finished.
- [ ] **Open at login** stays visually neutral when the pointer is over its label or switch: no blue row fill and no forced white text. The switch is aligned with the **right edge** of the menu actions and remains clickable. Arrow-key navigation should show a thin focus outline; **Space/Return** toggles it. If macOS requires approval or installation-location changes, instructions are readable. Restore your preferred setting.
- [ ] **Check for updates** displays checking, success, and retry or availability states as appropriate. Do not install an update just for this UI test.
- [ ] With a phone paired, the connection row shows the phone as active only while it is fetching stats. Settings lists it; the Revoke action is available (exercise only when you intend to re-pair).

## iPhone

- [ ] Launch **Stats** without a selected Mac. The unpaired/preview state is clearly identified; the sample readings do not look like live telemetry.
- [ ] After installing a **new build** on the iPhone, check the Home Screen icon uses the same blue chart logo as the Mac's About and Dock icons. Existing device installs do not pick up a rebuilt icon until updated.
- [ ] **Add Mac** presents nearby discovery and a manual IP/port fallback. Pairing instructions match the actual Mac menu, and the five-digit code is easy to enter.
- [ ] **Nearby Macs** shows the advertised macOS Computer Name **before pairing** (including after forgetting a Mac), not the `Stats Companion` Bonjour service name. After pairing, relaunching and reconnecting, the same friendly name remains visible; renaming the Mac updates the displayed label without losing the pairing.
- [ ] From the connected dashboard, open **Settings → Forget This Mac**. Cancel first and confirm the dashboard remains connected. Then confirm the destructive action: the saved pairing is cleared, Settings and the dashboard close, and the Mac reappears as an unpaired discovery option under its computer name. Pair again with a new five-digit code.
- [ ] **About This Mac** opens as the original bottom sheet (not a centered window), shows the native red/gray traffic lights and macOS-like hardware typography, and dismisses with the red close button. The deferred **More Info…** control and Regulatory Certification line are not visible. Check readable colors in both system Light and Dark modes.
- [ ] About This Mac initially opens at a compact height with the copyright comfortably above the bottom edge, no large empty white area, and readable 14pt specification rows without truncation. Expand the sheet and confirm it scrolls when space is limited.
- [ ] After connecting, **About This Mac** should show details without a loading screen. Close/reopen the sheet repeatedly, background the app, and relaunch: cached details should appear immediately while old entries refresh quietly. On a first-ever pairing, the initial placeholder may appear briefly; after **Forget This Mac**, details from the old pairing must never reappear.
- [ ] A wrong/expired code produces useful error text; retry is possible. With a correct code, the selected Mac appears and metrics update.
- [ ] On the overview, CPU, Memory, Storage, and Network use consistent card insets, icon sizes, text hierarchy, chevrons and rounding. Units and progress bars agree with the displayed labels (notably storage used vs free).
- [ ] **CPU details** requires updating both the Mac companion and the iPhone app. With the updated companion, overall CPU usage agrees with user + system (and user + system + idle is about 100%); idle CPU is never counted as busy. Check the live history chart, all logical cores, E/P/S groups on supported Apple Silicon, 1/5/15-minute load averages, uptime, temperature from CPU-associated thermal sensors, real residency-based frequency where available, and top processes. Confirm figures refresh and the view scrolls without lag or clipping. An old companion or unsupported sensor must show an honest unavailable state. SMC temperature keys and private IOReport frequency data can change with macOS or chip generation.
- [ ] **Compact CPU presentation** shows two correctly labeled gauges (CPU percent and average active clock in GHz), blue area history, color-coded E/P/S core activity columns, compact aligned details/load/frequency rows, and up to eight processes. Verify both appearances, smaller iPhones, large text, long process names, and older companions with missing optional readings. The second gauge's GHz reading must agree with the Frequency section (MHz / 1,000); its arc is measured against the fastest currently active CPU cluster, not a claimed hardware maximum. On the M6, **All cores** must be the core-count-weighted average of E (6), P (4) and S (2) frequencies, allowing integer display rounding.
- [ ] **Compact RAM presentation** shows a left semicircle with the Mac's actual **Normal / Warning / Critical** pressure state and needle; the right ring shows usage percentage with blue App, orange Wired, pink Compressed and gray remaining memory. Confirm a blue history area chart, a compact composition bar and Used / App / Wired / Compressed / Free / Swap rows, then up to eight processes ordered by memory bytes. The ring and chart should agree with total and used memory; readings update without vertical jitter or clipping.
- [ ] **RAM compatibility and accessibility**: with an older Mac companion, used/total and history can still render while pressure, breakdown and process rows clearly say unavailable. Unknown pressure must never appear as Normal, missing memory components must never appear as zero, and the colored breakdown must not be shown for inconsistent totals. Verify light/dark, narrow portrait screens, large Dynamic Type, long process names, VoiceOver names/values for both gauges and process rows, and an offline indicator after disconnection.
- [ ] **Disk details** opens from the Storage card with a **Disk** navigation title. Each mounted volume gets its own compact card and two separate measured rates. The explicitly painted chart must show **red filled writes exclusively above** its center baseline and **blue filled reads exclusively below** it. Check both directions when read and write magnitudes differ, when one is zero, and when write/read spikes occur at different times; downsampling must retain independent peaks for each color. The Y amplitudes are normalized independently for visibility while the labels remain truthful B/s. Confirm zero activity displays `0 B/s`, and no missing reading is invented. The blue capacity bar represents **used** space, while the line under it shows the free amount of total and **free percentage**. Let two readings arrive, then verify independently matched histories when disks appear or disconnect.
- [ ] **Disk detail row order** follows the design reference exactly: outside SMART, **Total read → Total written → File system → Connection type**. Below the centered **SMART** separator, show **Total read → Total written → Temperature → Health → Power cycles → Power on hours → Critical warning → Available spare**. Lifetime SMART totals must be distinct from the physical driver transfer totals. Don't insert the BSD device identifier or a redundant SMART status ahead of those rows. Missing warning data remains Unavailable, not an assumed “None”; drives without SMART can omit that section. Beneath the volumes, check up to eight top processes with independent Read/Write rates and accurate sorting. With an older companion, the startup volume still shows authentic total/free capacity while live I/O and per-process readings display unavailable states. Verify light/dark, 320-point portrait, Dynamic Type, long disk/process names, VoiceOver chart labels, and offline status.
- [ ] Each metric card opens its own detail page; the value, unit, recent chart, row labels and time stamp are legible. Wait for two samples before assessing the network throughput and line chart.
- [ ] Disconnect the Mac or briefly move the phone off the local network. A stale reading should have a clear **Disconnected** status rather than appearing fresh; reconnecting should restore live updates.
- [ ] Repeat in **Light/Dark**, larger iOS text, narrow portrait layout, and with VoiceOver. No truncation, overlapping controls, or inaccessible icon-only buttons.

## Report feedback

When something differs from the intended layout, send the **screen**, **appearance** (light/dark), **device or window size**, **steps to reproduce**, **actual result**, and **expected result**. Compare screenshots across builds for exact padding, font size, order, shadow, blur and separators.

Use any remaining findings to guide the next Settings-window and physical-iPhone testing round.
